# perf-dexopt

```bash
export ADB_SERIAL=192.168.1.169:PORT
./compile.sh    # speed-profile для всех пакетов, 10–20 минут, ждёт завершения
./revert.sh     # сброс компиляции к дефолту
```

## Зачем

Приложения на Android 13 ставятся в состоянии `verify`: код не скомпилирован, при
каждом запуске его крутит интерпретатор и JIT. Раз в сутки система докомпилирует
приложения по накопленным профилям (`speed-profile`), но только когда устройство
несколько часов простаивает на зарядке с выключенным экраном. Планшет, который
ночью показывает часы, до этого не доживает никогда: из 362 пакетов скомпилировано
было 29.

`cmd package compile -m speed-profile -a` делает то же самое принудительно.
Плюсы: быстрее холодные запуски, меньше JIT-нагрузки на CPU и батарею при каждом
открытии, чуть меньше памяти. Цена: 10–20 минут CPU на полную (греется,
подтормаживает), несколько сотен МБ под скомпилированный код. Функциональных
рисков нет.

## Как

Команда запускается **на самом планшете через `nohup`** и переживает обрыв adb
(по Wi-Fi это важно: `adb shell` с 20-минутной командой рвётся). Скрипт ждёт
маркер завершения в `/data/local/tmp/dexopt.log` и показывает число живых
`dex2oat`. До и после печатается статистика `status=` из `dumpsys package`.

Анимации здесь не трогаются: на этом планшете они уже 0.5.

## Результат на SM-P610, 2026-09-07

410 пакетов за ~13 минут на зарядке, `Success`. Состояние `dumpsys package`:
313 verify / 29 speed-profile → 68 verify / 252 speed-profile / 23 speed.
Под скомпилированный код ушло около 1 ГБ в /data, температура батареи не
поднялась выше 27 °C, крашей и ANR после компиляции нет.
